# 05 — Release engineering: what a release candidate needs on Windows 10, Windows 11 and Linux

Repo: `/home/user/bachelorpadplus_rust`, branch `claude/compassionate-wright-wwclxq` (HEAD `c9c89d7`). Read-only audit, 2026-09-25.
Legend: **P** = present, **Pa** = partial, **A** = absent, **n/a** = not applicable to that OS. Size: **S** ≤1 day, **M** 1–3 days, **L** 1–2 weeks, **XL** more than 2 weeks.

**Bottom line:** `ROADMAP.md:35` lists phase 20, "Packaging, signing, release and upgrade testing", as **Not started**. `project/tasks/14-hardening/04-packaging.md` is still the unfilled template, `artifacts/releases/` is empty, and `git tag` returns nothing. The code is a well-tested dev build. Nothing turns it into something a user can install. Three problems need fixing before any RC, whatever the packaging: the licensing is not stated, on Linux every message dialog depends on `zenity`, and on Linux the app declares none of the system libraries it needs.

## RC blockers per OS

### Windows 10
1. **Licensing is unresolved (all OSes).** No Slint licence choice, no `AboutSlint` or badge, no `LICENSE-*`, no third-party notices, and the About box states only MIT/Apache (`dispatch.rs:648-656`).
2. **Nothing installable.** No installer, portable zip or release profile (`Cargo.toml` has no `[profile.release]`), no tagged release pipeline or checksums, and the gate never builds or launches a release exe.
3. **No manifest or resources.** No icon, VERSIONINFO, comctl32 v6 manifest (which is what actually caused the rfd crash), `longPathAware` or supportedOS. Dynamic `vcruntime140.dll` is not guaranteed on a clean machine.
4. **Unsigned.** SmartScreen shows "Windows protected your PC", and Defender heuristics apply. Needs Authenticode with a timestamp on the exe and the installer.
5. **Failures are silent in release.** No panic hook, no log file (stdout is gone under `windows_subsystem`), no working `--version`. Default-app registration lives only as a `.reg` with no uninstall path (answer D8 through the installer).
   Also: the Win10 hand-off can only use the generic `ms-settings:defaultapps`. Decide the Win10 (ESU) support statement. Menus are mouse-only and invisible to screen readers.

### Windows 11
1. **Licensing** (same as Win10 #1).
2. **Code signing is harder to skip.** **Smart App Control** blocks unsigned, unknown-reputation binaries outright where it is on, on top of SmartScreen.
3. **Installer plus registration (D8).** A per-user installer writing the `bp-platform` HKCU plan, `SHChangeNotify`, and a clean uninstall. The app deep-links `ms-settings:defaultapps?registeredAppUser=BachelorPad%2B`.
4. **Manifest and resources, plus the CRT** (same as Win10 #3).
5. **Crash and log visibility, and a release pipeline** (release profile, pinned toolchain, `--locked` release build, checksums, SBOM, `cargo deny`).
   Also: accessibility of the custom menus (no keyboard or UIA roles), and a HiDPI and IME smoke test.

### Linux (X11 and Wayland; Ubuntu/Debian, Fedora, Arch)
1. **zenity dependency and a data-loss bug.** Every rfd message dialog runs through zenity. Without it, the startup recovery prompt counts as "No" and **deletes the recovery journal** (`bp-ui/src/lib.rs:383-400`), and the window cannot be closed with unsaved work (`:568-584`). KDE installs usually lack zenity. At minimum, declare zenity as a dependency and make only an explicit No discard.
2. **Runtime dependencies are undeclared.** Without `libxkbcommon-x11` the app panics at startup. The full set loaded with dlopen (xkbcommon, X11/xcb/Xcursor/Xi, wayland-client, dbus) plus fontconfig/freetype and xdg-desktop-portal needs package metadata for deb, rpm and Arch. Build on a Debian 12 or Ubuntu 22.04 glibc baseline.
3. **Licensing** (same as Windows; the `AboutSlint` route needs a Slint About window anyway, because rfd dialogs cannot host it).
4. **No monospace font.** "Consolas" is missing on Linux, so the default editor view falls back to a proportional font and `--editor-view` draws its caret in the wrong place. Bundle a monospace font through Slint `import` and add its licence to the notices.
5. **No desktop integration assets, and D9 is undecided.** No shipped `.desktop`, AppStream metainfo or hicolor icons. `Icon=bachelorpad` points at nothing. The runtime self-registration uses `current_exe()`, which breaks under AppImage and Flatpak. Decide D9 (reverse-DNS) before any package is published, because it cannot be changed afterwards without orphaning associations.
   Also: the association report reads only the user `mimeapps.list`; the Wayland clipboard (`arboard` without `wayland-data-control`, and a new instance per call); IME not verified on a real IBus/Fcitx session; screen-reader and keyboard access to the menus.
