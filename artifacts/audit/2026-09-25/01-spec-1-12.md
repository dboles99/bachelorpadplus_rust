# RC audit: specs.md sections 1 to 12

Branch `claude/compassionate-wright-wwclxq`, read-only audit, 2026-09-25. Every status below was checked in the code. I did not rely on ROADMAP or WORK_QUEUE for any of them.

**Status key**
- **Shipped**: reachable in the running app (a menu row, a key, or automatic behaviour) and tested, either in bp-ui or in the library it calls.
- **Built, unwired**: a tested library exists, but no code in `crates/bp-ui` or `apps/bachelorpad` calls it.
- **Partial**: some of the requirement works; the gap column says what is missing.
- **Missing**: there is no code for it.
- **Blocked**: waiting on a named decision (D-number) or a Slint 1.17.1 limit.

**Reachability facts used throughout** (checked with `Cargo.toml` reverse dependencies and `use` sites):
- `bp-notebook`, `bp-storage` and `bp-research` have no dependent except `tests/integration/Cargo.toml`. `bp-research` has none at all. bp-ui does not depend on any of them.
- bp-ui uses only one thing from `bp-buffer` directly: `bp_buffer::Buffer::from_text`, in the latency probe (`crates/bp-ui/src/lib.rs:1108`). `LargeFile`, `SizeClass`, `Access` and `WindowReader` have no caller outside `crates/bp-buffer`. `bp_files::load` (`crates/bp-files/src/load.rs:86`) calls `std::fs::read` on the whole file with no size check.
- The shell has two editor views:
  - The default `TextInput` view. Slint owns its caret, undo and text.
  - The opt-in `--editor-view` (`apps/bachelorpad/src/main.rs:88`). `bp-editor` owns its caret, undo and rope. It has no IME on Slint 1.17.1, and on Linux its caret drifts because of the Consolas font fallback.
  Many rows are live only in the opt-in view (they use `row`/`MenuItem { enabled: editor_view }`).
- Menus that are wholly `planned_menu(...)`: Notebook, Organize, Research, Run and Tools (`crates/bp-ui/src/lib.rs:240-247`, `crates/bp-ui/src/menus.rs:989`).
- No thread, `rayon` or async executor exists anywhere in bp-ui. Every operation runs on the Slint event-loop thread.
- `Cargo.lock` has no network client crate (no reqwest, ureq, hyper or curl).

## Biggest gaps, ranked by how much they block a release candidate

1. **Opening a large file is unsafe.** `bp_files::load` reads the whole file, and TextInput then receives it as one string. There is no size guard, so a multi-GB log can hang or OOM the app. The large-file engine (`bp_buffer::LargeFile`/`SizeClass`/`Access`) is built and tested but unwired. Minimum for RC: refuse or read-only anything over `HUGE_FILE_BYTES`, then wire the read-only viewer. (L)
2. **The two-view fork (D2) leaves the shipping view without core editing.** In the default TextInput view:
   - there is no line/column in the status bar;
   - Go to Line, Insert Date/Time and Duplicate/Move Line are greyed;
   - every keystroke copies the whole document.

   The opt-in view has none of those problems, but it has no IME (Slint 1.17.1) and its caret drifts on Linux (Consolas fallback). One view has to be made fit to ship, and a monospace font bundled. (L)
3. **JSON Format silently reorders keys.** `serde_json` has no `preserve_order`. Sort Keys is wired to the same action, and TOML Format drops comments with no warning. These are data-fidelity defects in shipped rows. (S)
4. **Everything runs on the UI thread.** That covers Find in Files (a synchronous directory walk), the 5-second checkpoint of every dirty document, and hashing and data operations. There is no parallelism and no cancel, so large folders or documents freeze the window. (L)
5. **Notebook and execution (section 12) are unreachable, and no executor exists.** Execution needs a cell view, a `bp-execution` crate, and per-OS process spawn and kill. RC needs this descoped formally, or roughly XL of work.
6. **The semantic layer stops at layer 1.** Tags, related notes, duplicate detection, topics, entities, semantic/hybrid search and semantic diff are all missing. `bp-storage` is blocked on D3 and providers on D1. Descope for RC, or XL.
7. **Markdown covers only source view and an outline dialog.** Preview/split is blocked on a rendering decision. There is no export, no Insert constructs, no TOC, and no heading operations. The outline counts `#` lines inside code fences as headings. (L)
8. **File-safety workflow gaps:**
   - no Compare in the external-change flow;
   - no revision history;
   - session recovery restores only dirty documents;
   - opened files get the open date as their "creation" date, which changes Semantic Rename names;
   - the collision and revision suffixes are unwired;
   - the Security menu's recovery readout is stale (`menus.rs:799`);
   - the status bar hides the full path behind every notice.

   (M overall; each item is S)
9. **Structured-data tooling is thin beyond validate, format and convert.** Missing: the JSON tree view, CSV/JSONL table view, filter/sort/query, statistics, dedupe, schema inference and JSONPath copy, plus YAML/JSON↔TOML and JSONL→CSV conversion. (L)
10. **No syntax highlighting in any format, and several Notepad-level editor features are missing:** multi-cursor, column selection, folding, indentation guides, a multi-select Open dialog, Ctrl+Tab and single-instance file hand-off. Drag and drop is blocked on Slint. Windows ANSI/1252 files are refused at open. (L)
