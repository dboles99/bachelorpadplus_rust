# ADR-0086: The Icon Ships Beside The Executable

**Status:** Accepted
**Date:** 2026-10-28
**Closes:** `project/WORK_QUEUE.md`'s P2
**Adopted from:** [bachelorpluslite ADR-0068](../../bachelorpluslite/docs/decisions/ADR-0068.md)

## Context

P2 was queued as *"an application icon, and the `.desktop` file
`bp_platform::editor::desktop` already knows how to write"*, and sized with a
warning: **"Windows takes it from the executable, which needs a build-time
resource — a new dependency, so an ADR."**

However, taking the inventory first — as this project's methodology
recommends — found that the downstream repository (`bachelorpluslite`)
already answered this question in [ADR-0068](../../bachelorpluslite/docs/decisions/ADR-0068.md).

The key findings from that ADR:
- Both Windows registry and Linux `.desktop` file already reference an icon
- The executable has never had an icon resource compiled in
- Slint 1.17 cannot decode ICO files, only PNG
- Therefore the icon must ship as a separate file beside the executable

## Decision

**The icon ships in the archive, beside the executable, and everything points
at it there.**

`bp_platform::editor::icon_file_name` (when added) will name it per platform:
- `bachelorpad.ico` for Windows
- `io.github.dboles99.BachelorPadPlus.png` for Linux and for the Slint window icon

The `.desktop` file will reference `io.github.dboles99.BachelorPadPlus` as
the icon name (theme name), and the PNG file can be placed in the appropriate
system icon directory or beside the executable for portable installs.

The Slint `AppWindow` gains an `in property <image> window-icon` and Rust
loads the PNG into it at startup. **Slint 1.17 cannot decode ICO**, so the
window icon **must** be the PNG regardless of platform.

### This removes the dependency rather than adding one

[ADR-0067](../../bachelorpluslite/docs/decisions/ADR-0067.md) (downstream) decided
there is no installer, and that decision **settles this one**. An installer is
the usual thing that places an icon into a system icon theme; with none, the
icon has to travel in the archive and be referenced from where it lands.

Which means the Windows registry does not need the icon *inside* the
executable at all. `DefaultIcon` takes any path, so it can point to the `.ico`
already sitting beside the binary — **and the build-time resource compiler
that P2 was sized around is not needed.** The file the archive was going to
carry anyway does the job.

## Consequences

**Release scripts updated** to stage both icon files (`bachelorpad.ico` and
`io.github.dboles99.BachelorPadPlus.png`) alongside the executable in both
Windows and Linux archives.

**`AppWindow` in `app.slint`** gains `in property <image> window-icon`.

**`lib.rs`** loads the PNG at startup and sets the `window-icon` property.

**Tests** will be added to verify the icon files exist and are staged.

## The lesson

> **A derived repository is a second reader of every decision this one made,
> and it re-checks premises for free.**

This ADR is directly adopted from the downstream repository's ADR-0068,
which answered questions this repository was still carrying. The downstream
repository's decisions are recorded decisions for this one too, and should
be checked before sizing work.
