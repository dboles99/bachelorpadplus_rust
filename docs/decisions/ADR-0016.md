# ADR-0016: Local-first CI

**Status:** Accepted
**Date:** 2026-08-17

> **Amended 2026-09-10 by [ADR-0082](ADR-0082.md): the premise below is no
> longer true, and it was true when written.** *"GitHub Actions is not
> available to this project"* describes a switch this ADR itself threw --
> `enabled: false` at the repository level -- rather than an absence. Hosted CI
> is restored, scoped to pull requests and `main` because this repository is
> **private** and its minutes are metered, with Windows billing at 2x.
>
> **Everything else in this ADR stands.** The local gate is still the one that
> authorises a push; the hosted one skips three stages it runs; and the warning
> that two gates which disagree are worse than one is honoured by naming the
> disagreement rather than pretending there is none.
>
> **The failure mode is worth more than the correction.** Nothing here was
> careless, and no mechanism in a decision document would ever have said the
> world had moved. It is trap 6 -- *a claim in the record is not a property of
> the repository* -- and the habit that catches it was installed for questions
> in `DECISIONS_NEEDED.md` and not for premises inside accepted ADRs, which is
> where this one lived for eighteen ADRs.


## Context

GitHub Actions is not available to this project. Commits and pushes work
normally; only hosted CI cannot run. A repository carrying a CI configuration
that never executes is worse than one carrying none, because the config
implies a gate that is not there.

## Decision

The authoritative gate is local: `scripts/Invoke-LocalCI.ps1`, wired into
`pre-commit` and `pre-push` by `scripts/Install-GitHooks.ps1`. It runs
formatting, a locked dependency check, clippy with warnings denied, and the
test suite, with an opt-in Linux leg through WSL and an opt-in pass over the
standalone spike workspaces.

`.github/workflows/ci.yml` is kept, kept correct, and set to
`workflow_dispatch` only, so pushes do not queue runs that cannot execute.

Actions is **also disabled at the repository level**
(`PUT /repos/:owner/:repo/actions/permissions`, `enabled: false`). Editing the
trigger only protects branches that carry the edit: pushing `main`, which was
two commits behind and still had `on: push`, queued a run that failed with
`startup_failure`. A per-branch guard cannot cover every branch that exists or
will exist, so the guarantee belongs at the repository.

## Consequences

- The gate only works once installed. `Install-GitHooks.ps1` verifies the
  executable bit, because a hook without it is skipped silently -- the
  hardest failure mode to notice.
- This machine sets `core.hooksPath` globally, whose pass-through stubs exec
  the repo-local hook. The installer therefore must not set a repo-local
  `core.hooksPath`, which would disable the global commit-msg hook.
- The hooks are bypassable with `BPAD_SKIP_CI=1`. That is deliberate: a gate
  with no escape hatch gets disabled wholesale the first time it is wrong.
- The local gate and the dormant workflow must be kept in step. Two gates
  that disagree are worse than one.
- Cross-platform verification depends on a Rust toolchain inside WSL. Without
  one, the Linux leg reports as skipped rather than silently passing.
