# ADR-0091: Hosted CI Is The Gate; The Local Gate Is The Fallback

**Status:** Accepted
**Date:** 2026-10-29
**Amends:** [ADR-0016](ADR-0016.md), [ADR-0082](ADR-0082.md)

## Context

[ADR-0082](ADR-0082.md) restored hosted CI but scoped it to pull requests and
`main`, because the repository was private and its minutes were metered. It
said so itself: *"If the repository goes public first, this gets cheaper and the
scoping above can be revisited."* The repository is public now.

Two hosted runs on 2026-10-29 showed what the scoping had hidden. **A workflow
that never runs is a workflow nobody has tested:**

- The branch's `ci.yml` listed fmt, check, clippy and test by hand and failed on
  Ubuntu at its first `cargo check`: it installed none of the system libraries
  Slint links (`fontconfig was not found`). It had sat unrun since ADR-0082.
- `main`'s `ci.yml` ran the gate script itself and passed every stage except
  `cargo deny`, which reported RUSTSEC-2026-0414 in `pulldown-cmark 0.13.4`.

Daniel's rule for the roles, which this ADR records: **hosted CI is how the
project is checked; the local gate is for when GitHub is backed up, or when
Actions is blocked because a bill is unpaid.**

## Decision

1. **`ci.yml` runs on every push and every pull request**, and on manual
   dispatch. A `concurrency` group cancels a run the next push supersedes.
2. **The hosted run is the gate.** It executes `scripts/Invoke-LocalCI.ps1`
   rather than a copy of its steps, on Windows and Ubuntu. One gate run in two
   places cannot disagree with itself; that is the point of keeping the script
   as its single definition.
3. **The local gate is the fallback.** When hosted CI cannot run, the full
   `./scripts/Invoke-LocalCI.ps1 -Linux` is the gate, and its green on both legs
   is what authorises a push, exactly as ADR-0016 had it.
4. **The hooks are unchanged.** `pre-commit` and `pre-push` still run `-Quick`.
   They are cheap, and they catch a format or clippy failure before a push
   queues a run that was always going to fail.

## What this does not change

- **Merging to `main`, and opening a pull request into it, still needs a human**
  (D13). The `protect-main` ruleset enforces the pull request mechanically.
- **No force pushes**, and no rewriting of pushed history.
- **A green hosted run is necessary and not sufficient for two things it cannot
  do**: the interactive manual pass in `project/NEXT_SESSION.md`, and anything
  that needs a person at the window. That was true of the local gate too.
- The parity gap ADR-0082 named is gone rather than managed: the hosted run
  executes the same script, so "stages the local gate runs and the hosted one
  does not" is empty. (The WSL leg runs as the Ubuntu job, not through WSL.)

## Consequences

- **Required status checks** for `main` should name the matrix jobs exactly:
  `gate (windows-latest)` and `gate (ubuntu-24.04)`. Not `check`, which is what
  the old file's job was called.
- `CLAUDE.md` standing authority 2 and its "The gate" section, `LOCAL_CI.md`,
  and the README described the old arrangement and are corrected with this ADR.
- The branch's gate script has no `cargo deny` stage and `main`'s has. The
  workflow installs `cargo-deny` regardless, so that the merge of the two does
  not also have to reconcile this file.
