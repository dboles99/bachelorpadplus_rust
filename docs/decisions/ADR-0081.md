# ADR-0081: The Licence Cannot Be Permissive, And The One In Every Manifest Was Never Available

**Status:** Accepted for the part that is a finding; **the choice among the
three routes is open as D26**
**Date:** 2026-09-10
**Amends:** [ADR-0054](ADR-0054.md), which added the two licence texts
**Relates to:** [ADR-0015](ADR-0015.md), which chose Slint and said nothing
about its terms

## Context

D26 asked which licence v1.1.1 ships under: the `MIT OR Apache-2.0` in every
manifest here, or the `GPL-3.0-only` the derived repository chose. **The
question had a premise, and the premise was false.**

`slint 1.17.1` and `i-slint-core 1.17.1`, read out of this workspace's own
vendored sources rather than out of any record:

```toml
license = "GPL-3.0-only OR LicenseRef-Slint-Royalty-free-2.0 OR LicenseRef-Slint-Software-3.0"
```

**None of the three is permissive.** This product statically links Slint, so the
licence of the whole work is constrained by whichever of Slint's three the
copyright holder elects. Two consequences, and the first is a defect that exists
right now:

1. **`MIT OR Apache-2.0` was never available**, under the GPL election. A work
   statically linking GPL-3.0-only code cannot be distributed under MIT. Every
   manifest in this workspace has claimed it since the scaffold commit, and
   `--version` prints it to users.
2. **Shipping proprietary requires a Slint licence** -- either
   `LicenseRef-Slint-Royalty-free-2.0` or `LicenseRef-Slint-Software-3.0`. Absent
   one, the only lawful licence for this product is **GPL-3.0-only**, which is
   why the derived repository is GPL-3.0-only ([ADR-0071 there]) and why it takes
   `-only`: Slint's grant is to version 3 and no other, so "or later" would offer
   terms nobody granted.

**Nothing in this repository has ever recorded a Slint licence election.**
ADR-0015 chose Slint on benchmarks and is silent on its terms; no manifest, ADR
or note names one.

## Decision

**Two halves. The first is settled; the second is Daniel's and is D26.**

### 1. The `MIT OR Apache-2.0` claim must not ship. Settled.

It is not a preference between licences, it is a claim the dependency graph does
not permit. It ships in three user-visible places -- `--version`, Help ▸ About,
and both licence texts staged into the release archive -- so it cannot be left
to be corrected later.

**Not corrected in this ADR**, because which string replaces it depends on
route 1 or 2 below, and writing a placeholder into the artefact is how the
current wrong string survived: it was written once and then inherited.

### 2. Which route, is open

| Route | What it costs | What it buys |
| --- | --- | --- |
| **Buy or register a Slint licence**, then ship proprietary | Procurement, with lead time, and terms this project has not read | The only route to a closed or paid product |
| **Ship GPL-3.0-only**, matching the derived repository | Forecloses a closed fork, including your own | Lawful today, zero procurement, one licence across both repositories |
| **Ship nothing until it is resolved** | The date | Never distributing under terms you do not hold |

**The exact terms and price of the royalty-free option are deliberately not
recorded here.** They are a `LicenseRef` -- the text lives with Slint, not in
the crate -- and an agent paraphrasing a licence agreement from memory is
exactly the wrong artefact for a decision like this one.

## Consequences

**A release is blocked on this, not merely informed by it.** The archive carries
licence texts and the binary prints a licence string, so there is no version of
1.1.1 that ships while the question is open.

**A second gap surfaced with it, and it blocks a release too.** This repository
has **no `THIRD-PARTY-NOTICES.md`**. The derived repository has one, generated by
a script with a gate stage that fails when it drifts. The other ~620 crates are
mostly MIT or Apache-2.0, and both require attribution when binaries are
distributed. That is true under *every* route above, so it is worth doing before
the route is chosen rather than after.

**The lesson, and it is the one ADR-0054 already taught from the other side.**
That session found every manifest claiming a licence **the repository did not
contain**, and fixed it by adding the two texts. This is every manifest claiming
a licence **the dependency does not permit** -- the same trap 3, one layer out.
Adding `LICENSE-MIT` and `LICENSE-APACHE` made the claim *look* discharged: there
were now files behind it, so the obvious check passed and the real one was never
made.

> **A claim can be false in a way that adding evidence makes harder to see.**
> Nothing in a build reads the licence string, so nothing would ever have failed
> -- and the fix that made it locally consistent is what stopped anybody looking
> further out.

**What would have caught it:** asking what the *dependencies* permit, not what
the repository contains. `cargo metadata` knows; `cargo-about` or `cargo-license`
would have said so on any day of the last twenty. That check belongs in the gate,
and it arrives with the notices file above.
