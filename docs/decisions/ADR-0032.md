# ADR-0032: Application id, registration on Windows, and a bundled monospace font

**Status:** Accepted
**Date:** 2026-09-25

## Context

Three platform-integration questions blocked release work (plan decisions 4,
5 and 6): D9, D8, and an unregistered one found by the sixth session.

- **D9.** The application id is this product's identity in every
  `mimeapps.list`, desktop database and AppStream catalogue. Changing it after
  anyone has installed the product orphans every association they made.
- **D8.** `bp-platform` generates the Windows registration values, but the
  app could only save them as a `.reg` file with no undo.
- **Font.** "Consolas" was hard-coded in six places. Slint resolves a family
  name literally -- no fontconfig aliasing, no generic `monospace` -- so
  Linux drew both editor views in a proportional font, and `--editor-view`'s
  one-advance-per-column caret drifted off the text.

## Decision

- **Application id: `io.github.dboles99.BachelorPad`.** Reverse-DNS, with no
  `+`, which desktop-entry ids do not allow. The on-disk directory name
  (`bp_platform::APP_DIR`, `bachelorpad`) does not change: it is a path, not
  an identity, and ADR-0029 has just moved its contents once.
- **Windows registration is the installer's job.** A per-user (HKCU)
  installer writes exactly the values `bp_platform::editor::windows`
  generates, and removes every one on uninstall. The app never writes the
  registry: it reports what opens each type and deep-links to Windows
  Settings (the app's own page on Windows 11, the generic page on Windows
  10). Portable builds keep the `.reg` route, with a matching unregister
  file.
- **DejaVu Sans Mono is bundled** and used on every surface that needs a
  monospace font, on every OS. Its licence (Bitstream Vera, permissive, no
  reserved-name clause) goes into the third-party notices.

## Consequences

- Every `.desktop` file, MIME package and AppStream id uses the new id before
  the first public package (plan M2-05, M2-07).
- The font is one of the few bundled assets, and it moves the binary size by
  roughly 300 KB.
- A test forbids "Consolas" in the `.slint` sources, so the literal-name
  trap cannot return.

## Implemented by

2026-09-26, release plan M3-01 (Windows registration half; decision 18:
an Inno Setup per-user installer and a portable zip).

- `packaging/windows/bachelorpad.iss` is per-user (`PrivilegesRequired=lowest`,
  no override), installs to `{localappdata}\Programs\BachelorPad+`, and sets
  `ChangesAssociations=yes`, which sends `SHChangeNotify` after install and
  uninstall. Its `[Registry]` section is generated by
  `bp_platform::editor::inno` from `windows::registry_values` for
  `{app}\bachelorpad.exe` and the same preset Set as Default uses
  (`desktop::PACKAGED_PRESET`), and every key passes `key_objection` first.
  `crates/bp-platform/tests/windows_installer.rs` fails if the shipped block
  differs by a byte; `cargo run -p bp-platform --example
  regenerate_windows_installer` rewrites it.
- Uninstall removes what install wrote and nothing else: `uninsdeletekey`
  on the product's own keys (the `BachelorPadPlus.<ext>` ProgIDs and
  `Software\BachelorPad+`, which gets a key-only entry because it holds no
  value of its own), `uninsdeletevalue` on the one value added to each shared
  key (`.<ext>\OpenWithProgids`, `RegisteredApplications`). The same line
  `windows::unregister_script` draws, through the same `owned_root`.
- An interactive uninstall asks, default No, before deleting the data,
  state and cache directories in `%LOCALAPPDATA%\bachelorpad` (paths
  generated from `bp_platform::dirs`); the roaming configuration directory
  is never deleted, and a silent uninstall deletes no user data.
- The portable zip ships no `.reg` pair, departing from the plan's wording:
  a `.reg` must name the exe's absolute path, which is unknown until the zip
  is unpacked. Its `README.txt` sends the user to File > Set as Default
  Editor > Save Files..., which writes the pair for wherever the exe is.

Verified on Linux only: the generator, its escaping, the uninstall flags per
key kind and the drift test run in `cargo test -p bp-platform`, and the
PowerShell scripts parse. Nothing has been compiled by ISCC or run on
Windows; `packaging/windows/Test-Install.ps1` is the check for a person on
the Windows 10 and 11 VMs.
