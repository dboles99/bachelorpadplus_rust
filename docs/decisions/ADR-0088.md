# ADR-0088: Local Embedding Provider via Candle

**Status:** Accepted  
**Date:** 2026-10-29

## Context

E2 of Phase 10 requires a `Local` embedding provider.  
[ADR-0056](ADR-0056.md) §4 states that such a provider:

- must ship or fetch its weights explicitly, never silently on first use;
- must work offline once present, because a `Local` that phones home is `Cloud` wearing a different name;
- must degrade to `None` with a notice rather than an error when the model is absent.

A local embedding model is a large dependency and possibly a downloaded file,  
which `CLAUDE.md` makes ADR material on its own.

## Options Considered

| Option | Pros | Cons |
| --- | --- | --- |
| **Candle** (Hugging Face) | Pure Rust, no native deps, runs offline, supports many architectures | Large compile times, large binary size (~50-100MB per model weights) |
| **ONNX Runtime** | Wide model support, good performance | Native dependency, requires separate model file distribution |
| **rust-bert / text-embeddings** | Pure Rust, simple API | Outdated, unmaintained, poor performance |
| **Sentence Transformers via Python** | Mature ecosystem, many pre-trained models | Requires Python runtime, not pure Rust |

## Decision

**Use Candle with a bundled sentence-transformers model.**

Specifically:
- **Dependency:** `candle = "0.3"` (or latest stable)
- **Model:** `sentence-transformers/all-MiniLM-L6-v2` (384-dimensional, ~80MB)
- **Distribution:** The model weights are bundled as a separate downloadable archive, not compiled into the binary

### Rationale

1. **Pure Rust:** Candle is implemented in pure Rust with no native dependencies, keeping builds reproducible across platforms (ADR-0001).

2. **Offline capable:** Once the model file is present, embedding computation works entirely offline — satisfying ADR-0056's requirement that `Local` must not phone home.

3. **Model distribution:** The weights are distributed as a separate file, satisfying "ship or fetch its weights explicitly" — users download a known model pack rather than having weights silently embedded.

4. **Degradation:** When the model file is absent, the provider returns `None` embeddings with a clear notice, as required.

5. **Quality:** all-MiniLM-L6-v2 produces high-quality embeddings (as measured by MTEB benchmarks) in a compact 384-dimensional space, suitable for semantic search over documents.

6. **Maintenance:** Candle is actively maintained by Hugging Face with regular releases.

## Consequences

- **New workspace dependency:** `candle = "0.3"` in `Cargo.toml`
- **New crate:** `bp-embeddings` to host the provider implementations
- **New assets directory:** `assets/models/` for bundled model weights (not checked into git, downloaded on demand)
- **Binary size:** The application binary itself does not grow significantly (no weights compiled in), but the download size for full embedding support increases by ~80MB
- **Platform support:** Candle supports CPU inference on all platforms; GPU acceleration is available on platforms with compatible drivers

## Implementation Plan

1. Add `candle` to workspace dependencies
2. Create `crates/bp-embeddings/` with:
   - `EmbeddingProvider` trait
   - `LocalProvider` implementation using Candle
   - `CloudProvider` implementation (E3) using reqwest for HTTP calls
   - Model download/management utilities
3. Wire providers into `bp-storage` for document embedding
4. Add configuration for model paths and cloud API keys
5. Add `Embeddings::None` degradation paths throughout

## Future Considerations

- Model upgrades: provide a mechanism for users to upgrade bundled models
- Multiple models: allow users to select between different embedding models
- Quantization: investigate 4-bit or 8-bit quantization to reduce model size without significant quality loss
