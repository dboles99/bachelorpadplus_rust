# ADR-0030: RC1 scope, and the locked decisions it defers

**Status:** Accepted
**Date:** 2026-09-25

## Context

`project/RELEASE_PLAN.md` measured the product against `specs.md` and against
what a release candidate needs on Windows 10, Windows 11 and Linux. Six locked
user decisions in `PROJECT_MEMORY.md` cannot be honoured in full by RC1
without extra-large work, and a locked decision is the owner's to relax,
never an agent's. They were put to Daniel as S1-S6 and answered on
2026-09-25.

## Decision

RC1 is the text appliance the tagline promises. Of the locked decisions:

| Plan | Locked decision | In RC1 | Deferred to |
| --- | --- | --- | --- |
| S1 | #7 notebook execution, mixed-language cells, run-selection | nothing visible; `.ipynb` opens as JSON; Notebook and Run menus hidden | 1.1 |
| S2 | #8 local semantic organisation: related notes, duplicates, hybrid search | semantic naming and deterministic (layer-1) analysis; Organize menu hidden | 1.2 |
| S3 | #9 memory mapping | chunked reads, as ADR-0027 already chose | **never**: the decline is permanent, and the README stops advertising it |
| S4 | #12 DPAPI, Windows Hello, Linux keyring | the rest of #12; Sign Document ships with its seed sealed in a passphrase `.bpadx` envelope (D5, option c) | platform keystores in 1.x |
| S5 | #15 personality modes | the icon set and brand assets | 1.x |
| S6 | #6 source-format highlighting | detection and the format label | 1.x; release notes say "source files open as plain text" |

Placeholder menus -- Notebook, Organize, Research, Run -- come off the menu
bar behind a `show_planned_menus` setting that defaults to off. No release
build shows a row for something that does not exist.

## Consequences

- The release notes carry these deferrals verbatim, so nobody reads RC1 as
  having dropped them.
- `bp-notebook`, `bp-research` and `bp-storage` stay unwired for RC1. That is
  now a decision rather than an omission.
- D5 is answered. Sign Document is no longer blocked; it is plan item M2-10.
